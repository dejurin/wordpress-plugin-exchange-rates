# 1.4.0 table-layout acceptance

This report covers the approved layout refinements on top of `main` commit `8b739905a9300c2e97ffa79821dc892ae97b757f`. It is a candidate for unreleased 1.4.0, not a publication record or a claim of identical appearance to 1.3.2.

## Behavior and implementation

| Problem | New behavior | Scope |
| --- | --- | --- |
| A compact table starts at one edge while its source caption floats at the opposite edge. | The caption follows the logical start edge: left in LTR, right in RTL. | Compact table captions only; full-width tables, converters and badges retain their existing placement. Source URLs and the information popup are preserved. |
| A small flag sits between a currency title and a heavy region label. | The flag aligns with the first title line; the region uses 0.8em, regular-weight secondary text. | New table label markup; existing flag assets and configured dimensions are retained. Flags cannot shrink inside flex layout. |
| The label column collapses to an ellipsis even though the table can scroll. | The text block has a 12ch minimum and wraps normally; wide tables continue to scroll inside their existing wrapper. | Labels in shortcode and native-widget tables. Full-width tables still fill the available width. |
| Full-width tables spread spare space across Code and Price, while the Code heading is centered independently of its values. | Currency absorbs spare width; all other columns stay content-sized. Code uses the same logical text edge in LTR/RTL. | Two CSS declarations scoped to the full-width marker; numeric right alignment and compact tables are preserved. |
| The base/input row ends before the history columns, or receives an invalid colspan. | The trailing cell spans exactly the visible Previous Close and Changes columns. | Independent of Code-column visibility, title mode, header visibility and history availability. The input underline remains inside the Price cell. |

Only three installable files change: `assets/css/public/style.css`, `src/Models/Dev.php`, and `src/Service/CurrencyTable.php`. Existing helper classes remain. New CSS is gated by new table/caption marker classes so old cached markup does not activate the new layout. JavaScript, calculations, source selection, option keys, shortcode attributes, widget identifiers, translations, dependencies and version metadata are untouched by this patch.

## Test-first evidence

1. Commit `1cad6d2` added the fixture, 20 regression scenarios, CI wiring and explicit legacy-CSS parity coverage before changing plugin code.
2. All 20 new scenarios failed on unmodified `main` and on the immutable 1.3.2 source. Representative failures: start-aligned caption expected `flex-start` but received `flex-end`; flag/title offset 15px; title width about 29px; base row covering 2 of 4 columns.
3. Commit `fa852a3` corrected the test fixture's decimal-comma expectations; production numeric behavior was unchanged.
4. An intermediate cross-browser run detected a Firefox flex issue: a 16px flag shrank to about 5.77px beside a long name at 320px. A scoped `flex-shrink: 0` resolved it. Existing flag-size assertions remain strict.

## Compact-column follow-up on 2026-10-18

User review found excessive space between Code and Price and a Code heading whose alignment differed from its values. Regression tests were committed first as `2c421c9`; all 16 scenarios failed on the preceding PR head `f673afb`. The fix adds only `width: 100%` to the first-column header cells and `text-align: start` to full-width table headers. Existing numeric-header rules retain their higher-priority right alignment. Automatic table layout sizes the other columns to their content; there is no hardcoded pixel width, new PHP markup, JavaScript or schema change in this follow-up.

- New Chromium column regressions: 16/16 pass after the fix. Both renderers, 320/480/900 px, LTR/RTL, hidden Code/headers/history, numeric containment, resizing and large amounts are covered.
- Firefox/WebKit: 152/152 combined, including all 16 column, 20 layout and 40 label scenarios per engine.
- Actual native-widget screenshots were captured at 320/480/900 px in both directions. Currency receives spare space; Code and Price stay together; compact captions, flag/region composition, readable labels and complete base rows remain intact.
- Isolated WordPress 7.1.3/PHP 8.3 smoke and saved-fixture verification passed again on the dedicated 19262 site. Manual-update and state-persistence integration and 116 WordPress formatting checks passed.
- Metadata, 56-file PHP lint, 841 formatter assertions, 1,157 percentage assertions and the 929-file package passed. The immutable 926-file 1.3.2 baseline and unchanged public signatures were verified again.

On the existing isolated test database, the plugin files were switched through 1.4.0 -> 1.3.2 -> 1.4.0 -> 1.3.2 -> 1.4.0. There was no reseeding, widget recreation, database restore or migration between transitions. Serialized settings, cached rates, both widget option sets, sidebars, active plugins, page content and the plugin's Cron events had the same SHA-256 at every step:

`5be7d3d99939bcf10d46be40a5c7b3b1027d4ef06566d0f4d444e34f117fbbb7`

The same protected-state digest also matched the snapshot taken before the browser runs. This demonstrates preservation of the tested saved configuration and upgrade/rollback path; it does not imply universal theme compatibility or pixel identity.

The older `table-isolation-wordpress.php verify` snapshot on the reused 19260 site reported an `update_timestamp` mismatch. The complete option value was identical before and after this work, so that seed snapshot was already stale; it was not reseeded to hide the failure. The newly isolated 19262 smoke site passed its seed/verify sequence. Upgrade/rollback evidence above uses fresh before/after serialized-state comparisons rather than that stale timestamp expectation.

## Limits and rollback

- The visual changes above are intentional: some tables become wider or taller instead of truncating labels. Narrow layouts retain horizontal scrolling. Theme CSS that deliberately overrides internal layout may need review.
- Cross-browser checks use Playwright desktop engines with mobile-width viewports; physical iOS/Android devices and all third-party themes were not tested. PHP 5.6 syntax/model checks were repeated, but a fresh WordPress 5.6 runtime installation was not part of this layout pass.
- Rates are synthetic. These checks do not establish live-provider availability or end-to-end production delivery.
- CSS parity tests remove only the new marker classes to test legacy markup. They intentionally do not assert pixel equality for the revised table layout. The dedicated layout/label tests check that output separately.
- After merge, rebuild the final release ZIP from the resulting `main`; an earlier 1.4.0 archive does not contain these changes. Purge HTML/CDN caches and rebuild combined/minified assets when installing the final release.
- Revert this PR to restore the preceding 1.4.0 table layout; no database rollback is required. Reinstalling the retained 1.3.2 archive preserves the tested saved state but reintroduces its known bugs.

All operations were local or within GitHub review. WordPress.org SVN was not written and nothing was published to WordPress.org. Raw local evidence is retained under the ignored `dist/layout-refinements-20261018/` directory in the canonical checkout; private state snapshots are not committed.
