# Exchange Rates 1.4.0 — bundled translation synchronization

## Scope

The shipped POT and the `en_US`, `uk` and `bg_BG` PO/MO catalogs now contain
the same 505 current messages. The template was extracted from the candidate
including the source-directory validation in PR #26 and cleanup in PR #27.
This change must follow those PRs; it does not merge or publish them.

Eight current keys were missing from each PO/MO: the updated 80+ description,
five trend/accessibility messages and two source-directory diagnostics.
The obsolete 86-source description was removed. The Ukrainian `Formatting`
label and Bulgarian `Force Data Update` label were corrected. Version,
extraction metadata and the case-sensitive `Install.php` editor setting
were synchronized.

No PHP application code, JavaScript, CSS, source English strings, saved options,
widget settings, shortcode contracts or version requirements were changed.
User-authored saved table headings are not translated or overwritten.

## Evidence

- Tests were committed first; the existing catalogs failed 27 assertions.
- Current catalogs pass 7,628 assertions using WordPress POMO on PHP 5.6.40,
  PHP 8.3.35 and local PHP 8.5.10.
- Every locale has 505 translated entries with no empty or fuzzy entries.
- GNU `msgfmt --check --check-format` accepts all three PO files.
- POT keys match fresh WP-CLI extraction; PO/MO keys, compiled values,
  printf placeholders, HTML tags/attributes and plural-rule headers agree.
- Comparison with the immutable 1.3.2 baseline preserves 497 existing English
  translations and 496 each for Ukrainian and Bulgarian. The only changed
  existing keys are the two labels above; the old description is replaced
  by the current key. All three original plural rules are preserved.
- CI additionally loads each MO through WordPress `load_textdomain()` and
  checks translated UI samples through the WordPress gettext API.
- Plugin metadata, all 56 PHP syntax checks and 929-file packaging pass.

These checks cover catalog integrity and selected UI wording, not a new native
speaker review of every inherited translation. Existing external WordPress
language packs may take precedence over bundled files on an installed site.

## Reproduction and maintenance

Use [WP-CLI extraction](https://developer.wordpress.org/cli/commands/i18n/make-pot/)
and [PO synchronization](https://developer.wordpress.org/cli/commands/i18n/update-po/):

```sh
set -euo pipefail
wp i18n make-pot plugin/trunk plugin/trunk/languages/exchange-rates.pot \
  --slug=exchange-rates --domain=exchange-rates
wp i18n update-po plugin/trunk/languages/exchange-rates.pot plugin/trunk/languages
```

Review new/changed translations and metadata before compiling. Do not accept
fuzzy matches automatically. Preserve existing correct translations, plural
forms, placeholders and HTML.

```sh
set -euo pipefail
for catalog in plugin/trunk/languages/*.po; do
  msgfmt --check --check-format --statistics -o "${catalog%.po}.mo" "$catalog"
done
python3 scripts/plugin.py check
python3 scripts/plugin.py lint
python3 scripts/plugin.py package
```

The WordPress CI job generates a fresh temporary POT, then runs
`tests/localization.php` through WP-CLI to check extraction and actual loading.
It does not change site language or stored settings.

## Rollback and publication boundary

Revert this catalog commit to restore the previous bundled translations.
No database migration or data rollback is needed. WordPress.org SVN remains
read-only; no publication or new final release ZIP is authorized by this PR.
