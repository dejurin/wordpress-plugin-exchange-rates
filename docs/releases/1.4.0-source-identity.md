# Exchange Rates 1.4.0 — retained source identity acceptance

Validation date: 2026-10-18. This report covers the P1 rendering fix on main `19300680cccd96dbc1f5a66637b497e670f1fee6`. It does not authorize merge or publication. WordPress.org SVN remains read-only.

## Defect and scope

After a failed source change, the selected source and the retained payload can legitimately differ. Previously, table/badge inversion and converter rate preparation used the selected source; table/converter captions did too. Changing CurrencyRate to ECB while ECB failed could turn the same retained USD-to-EUR rate from 1.25 into 0.8. The inverse source change also failed.

The three renderers now use the retained payload's source through the existing `RatesData::get_source()` helper. Converter base metadata uses the existing `get_base()` helper. The pending selection is retained for future retrieval. Missing legacy source/base metadata keeps the existing settings fallback. No provider request, cron, lock, option schema, public signature, shortcode attribute, widget identifier, frontend asset, translation or version change is included.

Tests were committed before production changes: initial reproduction `2863213`, followed by test-only fixture stabilization and cross-process restoration checks. The initial unmodified-main run failed 42 of 73 integration assertions and all eight failed-selection browser cases. The latter verify both source directions, desktop/mobile, and LTR/RTL. Eight additional matching-source browser cases preserve the published baseline contract.

## Limits and rollback

This PR is independent of PR #21: background refresh is not included. The combined checks above are an isolated test overlay, not a merge. Synthetic providers do not establish live-provider uptime. This patch does not serialize every manual/background writer, validate every malformed response, fix localized amount input, or claim compatibility with every theme, cache, multisite configuration or physical device.

Revert the three production PHP changes to roll back this fix; stored data needs no migration. Such a rollback restores the known incorrect conversion after failed source selection. Retain the matching README explanation when reviewing any rollback. Purge cached HTML so rendered rates and captions are regenerated after installation. Existing converter captions continue to refer to the initial currency pair; changing that contract is not part of this fix.

The earlier 1.4.0 acceptance report is historical; its deferred source-identity finding is superseded by this scoped evidence. No previously produced final ZIP includes this change until the reviewed PR is merged and a new archive is built from that main revision.
