## Removed duplication and inactive code

| Change | Why the result is preserved |
| --- | --- |
| Keep one `scrollbar-width: none` and one `-ms-overflow-style: none` in the responsive-table rule | Each removed declaration exactly duplicated an earlier declaration in the same block. Standard and vendor fallback properties remain. |
| Share `width: 100%` between `.w-100` and `.break` | Both selectors keep their individual specificity and names. The intervening rules contain no competing normal width declaration of equal specificity; important image dimensions and later converter rules retain their priority. |
| Remove normal converter input/select `:hover` background declaration | The same elements always receive `background-color: var(--bs-light) !important`. Importance wins over the hover selector's specificity, so the removed declaration could not affect the cascade. The swap button's effective important hover rule and `--bs-light-hover` remain. |
| Remove the extra semicolon after converter field padding | This removes an empty declaration without changing its value. |

This does not introduce a new hover effect, redesign the widgets, or change the approved RTL and SVG behavior.

## Rules inspected and deliberately retained

The audit covered both first-party stylesheets, PHP renderers, generated class names, frontend/admin JavaScript and interactive fixtures. A missing literal selector in a source search is not proof that its CSS is unused.

| Rule or pattern | Evidence / reason to retain |
| --- | --- |
| `.table-success`, `.table-danger` | `src/Service/CurrencyTable.php` emits them dynamically for the change column. |
| Caption button/info selectors | `src/Models/Dev.php` builds their names with `Plugin::PLUGIN_SLUG`; public JavaScript toggles the expanded information panel. |
| `.w-100`, `.break`, `.small`, `.text-truncate`, flag and region styles | Conditional table, full-width and regional-label rendering uses them. |
| Public `.text-center` | No first-party use was found, but it is an existing public utility. Absence from the repository does not exclude custom HTML/theme use. |
| Administrative `.alert`, `.alert-warning` | No first-party use was found. These global rules can affect other content on shared WordPress screens. Removing or scoping them requires a separate compatibility decision. |
| `.widget-inside.widget-inside` | The repeated class raises specificity for the legacy widget editor; deleting one occurrence changes the cascade. |
| Generic `.border` and converter-specific `.border` | The more specific rule protects a different cascade position. Removing it can change theme overrides even though the border value matches. |
| Table header/active background and RTL/right-alignment rules | Identical values serve different semantic or directional roles. They remain separate rather than coupling unrelated states for a small line-count reduction. |
| Explicit cell styles, `!important`, root custom properties and vendor fallbacks | Inheritance alone is insufficient with third-party theme rules. Broad deduplication, namespace changes or removal of old-browser fallbacks would exceed a behavior-preserving cleanup. |
| Repeated inline widget-form spacing and inline flag/badge styles | Form styles have inline specificity; flag dimensions and badge colors come from user options. Moving them into shared stylesheet rules would change priority or require a PHP/markup change. They are retained. |

Administrative CSS is byte-identical to 1.3.2. Its existing global selectors remain a future scoping concern, not a new regression caused by this patch. No claim is made that all remaining CSS is used on every page or that every legacy global rule is desirable.

## Verification method

`tests/browser/css-parity.spec.js` substitutes immutable reference CSS and candidate CSS on the same real WordPress DOM and state. It compares all computed properties, text/input values and geometry exactly, plus full-page screenshots. Coverage includes both table types, native widgets, converters, badges, flags/names/regions, trend arrows, input edits, expanded source information, table/converter input hover and focus, select/button hover, currency swaps, LTR/RTL, 320/1064 px and theme custom properties/overrides.

Screenshots use `threshold: 0.05` and `maxDiffPixels: 0`; there are no masked areas. Preliminary unchanged-CSS runs exposed Chromium SVG-edge rasterization differences in two pixels (RGB delta at most 8). Waiting for stable paints did not eliminate them. The documented small image-comparator tolerance addresses that noise; computed-style and geometry comparisons have no tolerance. A deliberate 61 px input-height mutation verifies that the comparison detects a real layout change.

The default reference is the approved 1.4.0 CSS before cleanup. On an actual 1.3.2 installation, `CSS_REFERENCE=legacy` additionally compares its original CSS with the candidate in LTR. Old RTL pixels are not an equality target because approved 1.4.0 RTL corrections intentionally change them; cleanup parity on legacy RTL markup uses the approved 1.4.0 CSS as its reference.

The isolated site uses project `er-css-20261016`, loopback port 19249 and dedicated `site`/`database` volumes, with guarded phase switches and read-only plugin mounts. No ordinary development site or existing gallery is used for mutation.

To rerun the committed CSS suite, prepare a separate seeded local site using the [development instructions](../development.md#css-parity-checks), then run:


The same suite was run with Playwright's `browserName` set to `chromium`, `firefox` and `webkit`. Each engine gets its own snapshot directory. The 1.3.2 LTR check additionally sets `CSS_REFERENCE=legacy` with the actual baseline plugin installed; the default reference on that installation covers cleanup parity on old LTR/RTL markup.

## Release and rollback boundary

This cleanup must pass PR review and CI before merging. Afterwards, build a new ZIP from the exact reviewed main commit and verify its contents; do not publish an older archive with the same version label by mistake. Purge page/CDN HTML caches and regenerate optimizer bundles when staging the update. Because 1.4.0 has not been released, users testing earlier local 1.4.0 candidates also need to invalidate assets cached under that same version.

Rollback of this cleanup requires only the previous public stylesheet from `cb097af1d04153dd8132a6a0214642491b5c5557`, preferably through a reviewed revert PR; no data rollback is necessary for the CSS change. A full plugin rollback to 1.3.2 restores its earlier known defects and appearance. Preserve site backups and follow the [release/rollback procedure](../release.md).

The finite matrix does not certify arbitrary themes, CSS-injection/optimization combinations, external CDNs, native assistive technology, physical devices or all supported browsers. The existing known plugin issues in the historical acceptance report remain outside this cleanup. Previous full optimizer, minimum-runtime and browser-installer results are historical evidence, not fresh tests of this CSS candidate.
