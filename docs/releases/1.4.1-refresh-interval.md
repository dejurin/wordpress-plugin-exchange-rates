## Behavior and compatibility

One 1800-second constant controls the recurring schedule and cache expiry
(`age >= 1800`). Normal bootstrap migrates default hourly events and the earlier
15-minute candidate without reactivation. Migration retains the earlier due time,
writes a replacement before removing obsolete events, checks storage failures,
and retries incomplete cleanup under the existing per-site lease. Explicit-source
events, the public hook and legacy callback remain compatible.

Flags smaller than 40 CSS pixels center vertically on the currency name; the
country occupies its own row below the group, aligned to its logical start edge.
At 40 pixels and above, flags center beside the combined name/country block.
Without a country there is one name/flag row at every size. Without a flag there
is no placeholder or reserved gap. LTR/RTL, shortcode/native-widget renderers,
regular/base rows, all flag types, original aspect ratios and compact/full tables
share one renderer. Rendering clamps flag widths to the existing 16–64 px UI
range without rewriting saved settings. New CSS only targets new markup; cached
legacy markup retains its rules. No JavaScript or new setting is introduced.

The source-directory success TTL stays one hour, manual cooldown stays 60 seconds,
and the failure retry and lease stay 300 seconds. No provider request is added to
frontend rendering. Version metadata remains 1.4.1; changelog, FAQ, POT/PO/MO and
the en_US/uk/bg_BG schedule label now describe the thirty-minute interval.
WordPress 5.6 and PHP 5.6 remain the declared minimums.

## Limits and rollback

WP-Cron depends on site traffic or an external runner. Page/CDN caches and already
open pages can still show old rates. More frequent checks do not guarantee new
provider observations. Synthetic tests establish neither API capacity nor live
provider availability; no production load test was performed. Browser checks use
Chromium, not physical phones or Safari. Theme overrides may require site QA.

Cron option writes are not transactional with arbitrary external writers. Failed
cleanup may temporarily leave duplicate work; subsequent bootstrap retries it.
The pre-existing in-flight-worker/deactivation race remains outside this change.

For rollback, let in-flight work finish, deactivate 1.4.1, restore verified 1.4.0
files, reactivate and verify hourly scheduling. Preserve rates, settings, widgets
and posts. Replacing active files alone does not guarantee the old recurrence.
No merge, production changes, SVN writes or publication are performed here.
