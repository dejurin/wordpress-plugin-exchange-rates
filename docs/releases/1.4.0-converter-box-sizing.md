# Converter box-sizing acceptance — unreleased 1.4.0

## Problem and scope

Without a theme reset, the existing converter input uses `content-box`: its declared 40px height becomes approximately 54.8px after padding and borders. Native selects and the swap button already occupy 40px. Astra supplies a reset that masks the defect; the site's additional minimum height produces 44px controls.

The patch adds one scoped rule for converter inputs, selects and `button.swap`: `box-sizing: border-box`. Fonts, padding, declared heights, icon assets, calculations and markup are unchanged. Both shortcode and native widget use the same rule. No universal reset or `!important` is introduced.

## Test-first evidence

Base: `084cc3c19c431b253abe54130f69be46395c6d43` (main after PR #24). Regression tests were committed as `b069954e9ff3f83a3009144b5d222b0b6a95b6dd` before the production CSS edit.

- Before the fix: 6 sizing failures (bare LTR/RTL at 320/390/1064px), 16 passes.
- After the fix: 22/22 Chromium cases pass with deterministic reset patterns.
- Full captured Astra 4.13.4/customizer/site CSS: 66/66 cases pass across Chromium, Firefox and WebKit, no retries or skips.
- PHP syntax: 56 files pass. Formatter: 841 assertions pass. Metadata and package validation pass for all 929 installable files.

The new tests cover two renderers per sizing case, four controls, containment and SVG vertical centering. Functional cases check amounts, swaps, selected currencies, zero values, neighbour isolation and unchanged initial caption/link. Existing CSS parity retains exact computed-style/geometry comparison with only this intended box-model correction added to the immutable reference.

## Upgrade and compatibility

The isolated WordPress 7.1.3 / PHP 8.3 site was first installed with published 1.3.2 (`e2fa9407b8068a3c8b34400a938da4962d30c43f`). Four functional baseline cases passed with actual legacy PHP, CSS and JavaScript. Settings, cached rates, a saved table widget and three pages were snapshotted before replacing only the plugin mount with the candidate. Verification after the change passed without reseeding or a data migration.

The complete existing Chromium suite passed **272/272** without retries or skips, including CSS parity, tables, RTL labels/numbers, percentage changes, arrows and administrator interactions. Saved settings/rates/widget/pages were verified unchanged again after this run.

Astra **4.13.4** was then installed and activated on that disposable site. Six additional cases passed with the actual WordPress-enqueued theme CSS (no style replacement): LTR/RTL at 320/390/1064px, both converter renderers, four equal-height controls, input/swap alignment and working amount/swap calculations. Mobile screenshots were visually reviewed in both directions.

The final focused suite additionally verifies that an unrelated input retains its own environment's box model, without an inline box-sizing override masking possible leakage. It passed 22/22 with deterministic resets and 66/66 with captured theme CSS across the three browser engines.

Local detailed evidence is retained in the ignored `dist/converter-box-sizing/` directory: `red-main.json`, `legacy-contract.json`, `full-browser.json`, `active-astra.json`, `green-main-final.json`, `real-theme-cross-browser-final.json` and `active-astra-{ltr,rtl}-390.png`. CI automatically discovers the new spec and runs it alongside the existing browser regressions.

## Intentional change and limitations

On a page that previously relied on `content-box`, the input and converter become approximately 14.8px shorter at a 16px root size. This is the approved correction; pixel identity with the defective bare 1.3.2 rendering is not claimed. Astra's existing border-box layout and the site's 44px minimum are preserved in the tested configurations.

Synthetic rates establish deterministic UI behavior, not live provider availability. Browser viewport tests are not physical-device tests, and captured theme CSS does not cover every theme or custom override. More specific or `!important` user styles may still override the plugin. Existing font differences and flex shrinking of the swap SVG are unchanged.

Rollback: revert the scoped CSS rule through a reviewed PR. No stored options, widgets, pages, schema, activation logic or migration need reverting. The old unequal-height behavior then returns on pages without a reset.

WordPress.org SVN remains read-only. This PR does not publish, merge or replace the previous final release ZIP. A fresh release package is required after an approved merge.
