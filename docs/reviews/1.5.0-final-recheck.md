## Phase 1: real VoiceOver speech on the candidate

Recorded native VoiceOver `last phrase` output in Safari on port 19335, with a
foreground and URL guard before actions and each speech read. No AX-tree text
was passed off as speech. Samples include:

| Flow | Recorded speech / result |
| --- | --- |
| Table field | `Amount in USD edit text` |
| Historical table | Full `Previous Close` heading and `Previous rate unavailable` for JPY |
| Valid input / JPY recovery | `Rates for 2 USD. EUR: 1.84; EUR previous close: 1.8; GBP: 1.54; GBP previous close: 1.6; JPY: 315.38; JPY previous close: unavailable` |
| Invalid amount | `Unable to calculate. Enter a valid amount.` |
| Zero after invalid input | All current results zero; JPY previous close remains `unavailable` |
| Converter fields | `Swap currencies button`, `From currency`, `To currency` |
| Converter result / recovery | `2 USD equals 1.84 EUR`; invalid input announces the error, then recovery restores the result |
| Five-currency badge | Each complete pair is spoken once with its position `1 of 5` through `5 of 5`; no `empty group` |
| Modal | `Data details web dialog`, close action, source, distinct Rate date/Saved descriptions and UTC values, disclaimer, plugin link, `1.5.0`, API link |
| Escape | Returns speech/focus to the date/details button |

Accepted speech recordings are identified in `voiceover/accepted-recordings.json`.
Setup-only captures, an initially unfocused capture and a keyboard-selection race
are retained but excluded from acceptance. The guarded helper now waits for and
verifies full selection before entering a bounded test value.

**Remaining speech refinement:** in the optional Changes column, VoiceOver reads
the percentage twice, for example `Changes Increase: 2.22% 2.22%`. The 1.4.2 ZIP
has the same visible percentage plus cell `aria-label` structure. This is distinct
from the fixed duplicate trend announcement in the Price cell. It is documented
under the previously deferred [1.5.6 accessibility work](../roadmaps/1.5.6.md),
not hidden by a claim of perfect accessibility. No additional production patch
was folded into this already tested package.

VoiceOver was switched off. Automatic permission cleanup timed out; the
maintainer removed the AppleScript-control checkbox and checked after reopening
VoiceOver Utility. A fresh accessibility snapshot independently confirms its
value is **0** (`voiceover/access-cleanup.txt`).

## Maintained tooling and metadata

- Reusable test snapshots allow another exact-ZIP LocalWP run without reseeding
  existing choices or overwriting prior snapshots.
- A test-only asset revision query prevents native browsers reusing older
  same-version 1.5.0 assets. It does not alter shipped resources.

  enable VoiceOver or grant AppleScript permissions.

  [WordPress.org allows Tested up to through an available release candidate,
  not a beta](https://developer.wordpress.org/plugins/wordpress-org/plugin-developer-faq/#what-version-of-wordpress-should-the-tested-up-to-value-be).

Tooling validation: six changed PHP helpers passed syntax checks; Python helpers
compiled; the 38-group registry validated; all eight registry unit tests passed;
`scripts/plugin.py check` confirmed version 1.5.0 and all 937 expected paths.

The requested technical reruns no longer block on the previous ZIP identity or
missing VoiceOver speech. Outstanding maintainer visual decisions and the
separate release/CI/publication boundary still apply. No WordPress.org, GitHub
publication or customer-site update was performed. Beta evidence is scoped to
Beta 2, not the future final 7.2 release; live-provider availability, arbitrary
theme/plugin combinations, multisite and formal WCAG/EAA conformance are not
established by these checks.
