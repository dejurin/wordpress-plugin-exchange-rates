## Installation, update and rollback

1. Installed the released ZIP with WordPress `Plugin_Upgrader`, then activated it.
2. Seeded synthetic saved settings, six cached currencies, two native widget instances, sidebar assignments, and a page containing all three shortcodes. The harness refuses to reseed.
3. Replaced the active plugin through the native updater with candidate 1.5.0, without saving settings or rebuilding widgets.
4. Rolled back through the same updater to the exact released ZIP, without restoring the database.
5. Reinstalled the same 1.5.0 candidate for review.

At every stage, a fresh WP-CLI process verified activation/runtime version, the complete installed file inventory and actual saved renderer output. Settings, rates, both widget options, `sidebars_widgets` and all saved pages remained **byte-identical**. The raw-state SHA256 remained `645788e6e3af0924116b1ab118b474e169da5493e040f7e48920d1a966a6a9a3`. Each stage retained exactly one recurring plugin refresh event.

After that complete round trip, a separate lifecycle check deactivated/reactivated the candidate and explicitly executed its WP-Cron event. Deactivation removed recurring/retry work; activation restored one recurring event; cron completed successfully without duplicates. Saved choices, rate payload, widgets, sidebar and pages stayed unchanged. Only the expected successful-refresh `update_timestamp` changed from `1793213149` to `1793213558`. This is recorded separately and is not misrepresented as an unchanged raw snapshot after a refresh.

## Reusable tooling and boundaries

- `scripts/localwp-acceptance.py` guards the named site, loopback URL, LocalWP identity, ownership marker and package hashes; records commands and evidence. Uses the existing native ZIP/state verifier with a configurable package directory.
- `tests/acceptance/localwp.php` and `localwp.html` render real persisted configurations without `pre_option` substitution and run the browser scenarios. Only outbound provider HTTP is synthetic.
- `tests/regressions/localwp-lifecycle.php` separately verifies deactivation, activation and cron; `native-state.php` shares the read-only snapshot function with native upgrade checks.
- `scripts/localwp-report.py` assembles the inspectable local report and verifies installed/source ZIP parity, initial values and rollback pixels. `ER-localwp` is registered in the permanent catalog.

This run uses HTTP localhost, a single site/theme and synthetic rates. It does not establish live-provider delivery, HTTPS, multisite, arbitrary optimization/security-plugin compatibility, or accessibility certification. Existing phase 1/2 human visual decisions and VoiceOver evidence gaps are unaffected. The site remains on 1.5.0 for review; automatic updates and automatic cron spawning are disabled only on this test site.
