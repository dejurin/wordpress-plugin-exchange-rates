## Changes

1. Overflowing history tables use the accepted adaptive layout: wrapping
   headings, flexible currency labels, symmetric compact padding below 320 CSS
   pixels of available space, then abbreviated default history headings if
   needed. Fitting layouts retain their geometry; font size and numeric precision
   are unchanged. Saved custom headings are preserved. Full accessible names
   and title text remain available for abbreviated headings.
2. Oversized values remain intact. A visible scrollbar, translated instruction
   and keyboard-focusable region make remaining horizontal overflow discoverable.
   Tables that fit do not acquire an extra keyboard stop.
3. Missing previous JPY rates no longer invalidate valid table amounts. The
   server's unavailable-history sentinel remains a dash, not a fabricated zero.
   Invalid input and unrepresentable calculations still produce an error.
4. Added four translatable strings and synchronized en_US, uk and bg_BG PO/MO
   catalogs. Added changelog entries and two permanent regression groups.

Plugin files changed in this integration: `assets/css/public/style.css`,
`assets/js/public/common.js`, `src/Service/CurrencyTable.php`, `src/Plugin.php`,
`readme.txt` and the translation catalogs. No option schema, shortcode/widget
identifier, stored amount or provider data contract changed.

## Test-environment findings

- The first local Chromium process could not start inside the sandbox; the
  authorized isolated browser run produced the actual red evidence afterward.
- The first native receipt compared differently serialized CSS floating-point
  sizes and re-entered a grouped display amount as raw input. The harness now
  allows less than 0.01 CSS px serialization variation and restores the numeric
  `data-amount`. Raw grouped input remains intentionally rejected.
- The first in-app Chromium matrix used cached assets from the previous **1.5.0**
  build. The local theme fixture now adds a content-derived asset revision for
  repeated candidate testing. This changes only test URLs, not plugin content.
  Production upgrades from 1.4.2 already change the plugin asset version.
- The shared review site's old saved-state snapshot differs in settings, a
  table widget and pages, so its old snapshot is not used as upgrade evidence.
  It was not overwritten or reseeded. The eight fresh, separately owned native
  environments independently verify unchanged raw state across upgrade,
  rollback and restoration.

## Reproduction and rollback

Run the permanent tests with `WP_TEST_URL` set to the owned disposable WordPress
site and the fixture mounts described in the development documentation:

```sh
python3 scripts/plugin.py check
python3 scripts/plugin.py lint
python3 scripts/regressions.py check
WP_TEST_URL=http://127.0.0.1:19335 npx --prefix tests/browser playwright test \
  -c tests/browser/playwright.config.js table-fit.spec.js table-history-input.spec.js \
  table-columns.spec.js table-layout.spec.js trend-arrows.spec.js \
  amount-input.spec.js footer-modal.spec.js
```

The installed review is at `http://127.0.0.1:19335/?er_table_fit=review`.
Its guarded MU loader uses `tests/acceptance/table-fit-preview.php`; the retained
pre-fix geometry is mounted as `/acceptance/table-fit-baseline.json`. The former
prototype harness is preserved in `prototype-harness/`. The live review no longer
injects its prototype CSS or behavior.

Rollback uses the retained previous ZIP through the WordPress upgrader. The
isolated native matrix also verified rollback to each released baseline and
restoration of the new candidate. No database migration is required.
