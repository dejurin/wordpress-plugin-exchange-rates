# Exchange Rates 1.5.0: numeric-axis correction

Date: October 29, 2026. The maintainer accepted the correction and retained right
alignment in RTL. This receipt describes the initial focused checks; subsequent
full verification is recorded in the [RC receipt](1.5.0-rc.md). No publication.

## Problem and correction

Rows with a trend arrow placed the number 18 px left of unchanged or
missing-history rows. The Price heading and static/editable base amount did not
share that numeric edge. The new regression reproduced this before the fix.

The table renderer marks the price cells and only enables the trend lane when a
rendered currency has a trend. CSS reserves 18 px and positions the 14 px arrow
separately with a 4 px gap. The heading, every quoted price and the base amount
therefore share one right edge. Full/compact, static/editable and LTR/RTL tables
use the same rule; a table without trends keeps its previous content inset.
The axis aligns the whole formatted value: an after-value currency symbol stays
part of that text run. This is not a change to decimal-place alignment or symbol
ordering; existing RTL/symbol-order cases remain covered by the adjacent tests.

No numbers, timestamp meanings, source selection, option schemas, widget IDs,
shortcode attributes, JavaScript, translations or emoji assets changed. The
converter and badge source files are unchanged. Existing footer styles remain
separate from the price-cell rule.
