## Isolated table proposal

Historical preview record: the following sections describe the original,
unchanged-package proposal. The live URL now runs the approved installed
integration documented in [the new receipt](1.5.0-table-integration.md).

Preview URL: `http://127.0.0.1:19335/?er_table_fit=review`.
Both panes use the unchanged installed 1.5.0 package; only the right pane loads
the test proposal. Test source is `tests/acceptance/table-fit-*`.

The guarded loader is a symlink in the isolated `er-integrated150-20261028`
WordPress container's MU-plugin directory. It requires local environment mode,
the synthetic test flag, a loopback site URL and an explicit `er_table_fit`
parameter. Normal acceptance pages do not load the proposed styles or behavior.
No plugin files, public site, saved options, rates, widget settings or candidate
ZIP are changed. Test reports are saved under `wp-content/table-fit-preview/`.

Rollback: remove the query parameter to return to normal rendering. The proposal
can be fully disabled by unlinking only that test MU-plugin symlink. Do not
replace the reviewed ZIP or remove any existing acceptance evidence.

The prototype uses English-only overflow hints. A production integration must
localize any new strings, add permanent regression coverage and retest the new
package before inheriting any release-readiness claim.

The proposal first checks whether the original table fits. Only overflowing
history tables receive wrapping headings and a flexible label column. Containers
below 320 CSS pixels also receive symmetric compact horizontal cell padding.
If necessary, the two default history headings become `Prev.` and `Δ %`;
their full accessible names and hover titles remain available. Custom header
labels must not be silently replaced. Still-oversized numeric data uses an
explicit scrollbar, visible instruction and keyboard-focusable scroll region.
Font sizes, numbers, percentages and the plugin footer are preserved.

## Preview verification

Evidence: `dist/table-fit-preview-20261028/final.json`, recorded in the in-app
Chromium browser on October 28. The earlier attempts remain separate.

- 63/63 layout cases pass across five themes, 320/390/640 px, both sources,
  native widgets, flags, full names, large amounts and RTL.
- All ordinary history configurations show the last column without scrolling,
  including all eight originally reported Astra/Kadence combinations.
- 60 cases fit fully. Three large-amount cases retain explicit, accessible
  horizontal scrolling. Real right-arrow input reached the last column on
  Kadence at 320 px; `keyboard-scroll.jpg` retains the screenshot.
- All 25 cases that already fit retain their cell geometry. Values and numeric
  typography match before/after throughout the matrix.
- 517/521 individual assertions pass. Four retained interaction failures are
  the before/after recovery checks in the two native-widget cases described
  below; the complete suite is **not** green.
- All 937 source and installed plugin files still match the original candidate;
  its ZIP SHA256 is unchanged. PHP lint, JavaScript syntax checks and
  `git diff --check` pass for the preview tooling.

These results cover the prototype only. This change has not been integrated into
`plugin/trunk/` or tested as a new ZIP in Safari, Firefox or VoiceOver.

## Additional input finding

The synthetic mixed-history case has no previous JPY rate. After entering a
valid amount following invalid input, the amount field retains
`aria-invalid="true"` on both the unchanged package and the proposal, in native
widget cases on Astra and Kadence at 320 px. Values for available rates recover.
This is an existing calculation/validation issue, independent of table fitting;
it is not fixed or accepted by this visual preview. Keep the failing interaction
assertions in the evidence. Do not report the complete interaction suite as green.
