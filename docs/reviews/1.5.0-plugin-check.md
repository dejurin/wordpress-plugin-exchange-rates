## Commands and coverage

Both versions used the same checker and options, with no exclusions added:

```sh
wp plugin check ./wp-content/plugins/exchange-rates \
  --mode=update --format=json \
  --include-low-severity-errors --include-low-severity-warnings

wp plugin check ./wp-content/plugins/exchange-rates \
  --require=./wp-content/plugins/plugin-check/cli.php \
  --mode=update --format=json \
  --include-low-severity-errors --include-low-severity-warnings
```

The first command uses the checker's default static mode. The explicit early
bootstrap enables runtime checking in the second command, as described in the
[official CLI documentation](https://github.com/WordPress/plugin-check/blob/trunk/docs/CLI.md).
The target plugin was active. The checker contains **29 default static checks
and five runtime checks**; all five categories were enabled: general,
plugin_repo, security, performance and accessibility. The runtime checks cover
enqueued script/style sizes and scopes, and non-blocking scripts. The temporary
checker object-cache drop-in was absent after cleanup.

No AI analysis, ignored codes, ignored warnings, ignored errors, `.pcpignore`,
additional excluded files/directories or baseline-driven suppression was used.
Default file-scan exclusions remain `.git`, `vendor`, `vendor_prefixed`,
`vendor-prefixed` and `node_modules`. Installed-file identity does not mean all
937 files were scanned. Experimental checks were not requested; this pinned
checker lists the same 34 checks with or without that option.

No untrusted raw input reaches these reported sinks. No suppression or code change was made. |

The two external SVG findings remain unresolved. They require a focused change
or an explicit documented policy disposition before this gate can be closed.
Their presence in 1.4.2 is provenance, not approval. A possible focused fix is
bundling the exact used emoji SVGs with verified license and attribution;
substituting the existing local flag artwork would change the accepted visual
contract. Neither change was made in this check. See also the official
[directory guideline on unrelated offloaded assets](https://developer.wordpress.org/plugins/wordpress-org/detailed-plugin-guidelines/#7-plugins-may-not-track-users-without-their-consent).
