Table attribution goes to base-specific FX Source pages; converter attribution to its currency-pair page; badges retain the base-currency destination. Visible attribution links preserve the agreed rel behavior; all modal links have nofollow/noopener/noreferrer.
2. Compact names for all 86 configured sources and the attributed MIT Heroicons source marker. Existing full source names/URLs remain available in the dialog.
3. One shared native dialog, emitted only when needed, with source, Rate date, Saved, `[ExchangeRatesWP]`, actual plugin version and API attribution. It starts with an inline hidden guard and never becomes an inline page fragment if native modal support is absent, throws or is not really modal.
4. Visitor-local footer dates retain their UTC instant. Details display UTC. Invalid or missing timestamps remain explicitly unavailable.
5. Existing approved accessibility behavior is ported: unique field IDs, localized names, live result/error messages, error associations, hidden badge list descriptions, one trend description per value, visible focus, dialog initial focus/trapping/return, and external-link notices. This is not a WCAG/EAA certification claim.
6. Existing zero-input/control-label/dependency work is retained. All public source UI strings remain translatable; en_US, uk and bg_BG catalogs are synchronized. Plugin/readme metadata is now locally 1.5.0.
7. Permanent regression tooling now covers unit suites, ordered WordPress suites, browser fixture preparation and post-run persistence, and native historical ZIP upgrade/rollback. CI also runs the new standalone footer assertions.

## Defects exposed and corrected during integration

- A queued native dialog close event could hide a newly reopened dialog. Close cleanup is now synchronous; stale close events do not close a subsequent open.
- Initial JavaScript table recalculation could misread server-localized amounts such as `1.234,56`. Initial server values are retained; trend decoration uses numeric metadata, and calculation waits for actual input.
- Early script localization could capture English before a later fixture/site locale was selected. Messages are localized immediately before footer scripts are printed.
- WordPress 5.6 sanitization stripped required dialog attributes from native converter widgets. Both native widgets now use the shared explicit HTML allowlist. The first minimum-runtime matrix exposed this; the final full matrix passed after the fix.
- The new test runner initially stopped after formatting fixtures, leaving their settings for browser tests. The browser command now owns the required table-isolation seed and post-run verification. This was a harness defect, not a plugin data regression.
- Historical visual tests were reading deliberately hidden screen-reader descriptions as visible numeric text or geometry. Their numeric/geometry assertions now exclude only `.er-a11y-sr-only`; separate tests still verify those descriptions. No rounding tolerances or expected visible values were loosened.

## Visual findings requiring maintainer review

- **102 REVIEW cases:** converter inputs/selects have the stronger border from the approved accessibility prototype: `rgba(0,0,0,.05)` becomes `#858b93`. This includes multi-widget pages containing a converter. All other measured body/control properties and displayed values match. The stronger border still needs explicit visual acceptance; it is not silently treated as an allowed footer change.
- **8 REVIEW cases:** history-enabled tables at narrow widths have horizontal overflow in both 1.4.2 and 1.5.0. Measured geometry and numbers are equal. This is a pre-existing limitation, not a new regression; it remains visible in the report for a decision.
- **208 MATCH cases:** measured body values/geometry/styles match. This does not claim screenshot pixel equality or human approval of the changed footer.
- Header, laboratory controls and theme footer are outside the plugin body measurements. The UI retains the real theme context; differences in test-page titles are not plugin output.

The 318-case matrix includes all 22 named compositions on Astra and Kadence at 320/390/640 pixels for ECB and CurrencyRate, plus standard compositions on the other three primary themes. Historical tests separately exercise flags, localization, custom CSS and other rendering contracts. This is a defined coverage set, not every possible theme/plugin combination.
