## Visual findings

- All three mobile rollback screenshots match their own 1.4.2 baseline pixel-for-pixel.
- The six individual table/converter/badge screenshots match the stable WP 7.1.3 run at both widths.
- The modal has a small cosmetic difference in its lower plugin-identity row: the stable site's DOM contains WordPress SVG emoji replacements; the beta site's DOM retains the native `⚡` and `🚀` characters. Matched viewport captures and `emoji-dom.json` demonstrate the difference; modal operation and viewport fit pass. This observation is not a claim that every 7.2 installation always uses native emoji. No plugin CSS/content changes were made to conceal it.
- An initial two-tab settled-image comparison had mismatched viewports and is excluded from acceptance. `*-modal-matched-*.jpg` and `matched-emoji-metrics.json` are the valid comparison; both DOM and image dimensions were checked at 390×780 and 1280×780.

## Maintained coverage and limits

The report generator now uses each site's recorded identity/address and WordPress version, and verifies an optional pinned core archive before reporting success. The beta row is recorded under the permanent `ER-localwp` contract. Keep future beta/RC runs in new sites/evidence directories and retain the exact archive/version; do not silently replace Beta 2 evidence with a moving nightly.

This establishes the tested behavior on **7.2-beta2**, not the future final 7.2 release. Plugin `Tested up to`, version metadata and source files are unchanged. Live providers, HTTPS, multisite, arbitrary third-party plugin combinations and VoiceOver are outside this beta run. Human visual acceptance (including the emoji difference) and the outstanding exact-package VoiceOver recording remain separate release gates. Nothing was published.
