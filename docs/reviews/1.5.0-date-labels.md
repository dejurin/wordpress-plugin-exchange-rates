# 1.5.0: restore published date labels

Date: 2026-10-28. The maintainer clarified that the requested original labels
refer to published 1.4.2. This supersedes the interim Rate date/Saved decision
recorded in the [catalog refresh receipt](1.5.0-release-docs.md).

## Published contract and change

The verified 1.4.2 ZIP has SHA-256
`813028842039f6bb51badb0c22271cd3192bd7d8b9c2b5597d89a79b809f248d`.
Its `src/Models/Dev.php`, lines 110–111, renders these labels in this order:

| Label | Existing field | English | Ukrainian | Bulgarian |
| --- | --- | --- | --- | --- |
| First date | `put_time` | Check: | Перевірка: | Проверка: |
| Second date | `local_time` | Latest change: | Останні зміни: | Последна промяна: |

The shared 1.5.0 modal now uses exactly this wording, order and translations.
Timestamp values, parsing, UTC details and visitor-local footer display are
unchanged. Existing explanatory titles still distinguish the time the data
service saved an entry from the source data time. The historical wording does
not add a new source-verification event or a numerical-change guarantee.

`Footer.php` is the only changed runtime source file. No CSS, JavaScript,
calculation, data-fetching, storage or API contract changed. POT and all three
PO/MO pairs were synchronized. All translations other than the two restored
labels match the previous package. The catalogs now contain 531 entries:
`Check:` and `Latest change:` were added and the unused `Saved` removed;
`Rate date` remains used by the disabled footer control's accessible fallback.
